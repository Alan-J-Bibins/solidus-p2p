# Review 3 Demo

A real two-browser file transfer over Solidus' WebRTC transport, plus a measured
Solidus-vs-raw-WebRTC comparison and copies of both Review 2 apps.

## Contents

- `src/main.ts` + `src/style.css`: the showcase — peer session management, real
  file chunking + transfer + reassembly + SHA-256 verification, a measured LOC
  comparison, and an honest swarm-chunking status section.
- `src/loc-data.json`: generated by `scripts/loc-compare.mjs`; measured, not hand-typed.
- `review-2-source/with-solidus/`: unmodified copy of `apps/review-2-demo`.
- `review-2-source/without-solidus/`: unmodified copy of `apps/review-2-demo-raw`.

## What's real here

- **File transfer**: the selected file's actual bytes are sent chunk-by-chunk over
  a live `RTCDataChannel` (via `@solidus-p2p/core/networking`'s `createWebRTCTransport`,
  `broadcastChunk`/`onChunk`), reassembled on the receiving browser, and verified with
  an independently computed SHA-256 hash. Nothing is simulated with timers or fake peers.
- **Chunking**: a from-scratch, browser-compatible gear/rolling-hash content-defined
  chunker — explicitly _not_ the native `fastcdc` npm package, which dynamically
  `import()`s a compiled `.node` binary and cannot run in a browser bundle. This app
  imports `@solidus-p2p/core/networking` rather than the package root specifically to
  avoid pulling that plugin into the browser build (see the comment at the top of
  `src/main.ts`).
- **LOC comparison**: run `npm run loc --workspace=review-3-demo` to regenerate
  `src/loc-data.json` from the real `review-2-source/*/src/{main,p2p}.ts` files.
- **Swarm chunking**: absent. See the "Swarm chunking status" section in the app
  for the evidence (the chunk transport fans one sender's bytes out to every
  connected peer — there's no chunk ownership, discovery, or multi-source retrieval).

## Running a two-computer transfer

1. From the repo root: `npm run dev --workspace=signaling-server` (listens on
   `ws://0.0.0.0:8080`).
2. From the repo root: `npm run dev --workspace=review-3-demo`.
3. On each computer, open the review-3-demo URL, set **Signaling server** to
   `ws://<host-machine-LAN-IP>:8080` (not `localhost` unless both browsers are on
   the same machine) and use the same **Room name** on both, then click Connect.
4. Once "Connected peers" shows at least 1 on both sides, pick a file on one
   browser and click "Send to connected peers". The other browser shows live
   chunk reception, then verification, then a download button.

Requires the two computers to be able to reach the signaling server's port and
to successfully complete a WebRTC ICE handshake (the default STUN server is
`stun:stun.l.google.com:19302`; a restrictive NAT/firewall may need a TURN
server, which this demo does not configure).

## Run from repository root

```bash
npm run dev --workspace=review-3-demo
```

The repository declares npm `11.18.0` and Node.js `>=22.18.0` in its root package metadata. Use the repository's required versions if workspace setup or scripts reject the local toolchain.
